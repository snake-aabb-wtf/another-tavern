# 群聊 E2E 验收清单

本文记录第一阶段群聊核心链路的自动化验收范围。自动多轮不属于本阶段验收目标。

## 自动化验收

在仓库根目录执行：

```bash
pnpm test
```

群聊相关验收覆盖：

| 场景       | 验收内容                                                         |
| ---------- | ---------------------------------------------------------------- |
| 创建与详情 | 创建两个角色的群聊，首条 greeting、成员顺序和角色身份正确落库    |
| 成员设置   | 成员顺序、静音、talkativeness 可持久化；群聊至少保留两个成员     |
| 手动发言   | `speakerId` 选择正确角色，SSE `meta` 与 assistant 消息带角色身份 |
| 列表轮换   | `list` 策略按成员顺序选择下一位非静音角色                        |
| 强制发言   | 静音角色默认拒绝，`force: true` 才允许生成                       |
| 失败与重试 | 失败用户消息原地重试，不产生重复用户消息，并恢复原 speaker       |
| 重新生成   | 沿用原 assistant speaker，并追加 swipe 候选                      |
| 刷新恢复   | 重新读取 session detail 后，成员、设置、消息与身份不丢失         |
| 并发保护   | 同一会话同时生成时，第二个请求返回 `generation_in_progress`      |
| 取消       | 客户端断开后用户消息标记为 `cancelled`，speaker 身份保留         |

## 浏览器冒烟

配置一个可用的 OpenAI 兼容上游后，执行 `pnpm dev`，打开 `http://localhost:5173`：

1. 在侧栏点击「新建群聊」，选择三个角色并调整顺序。
2. 打开成员设置，静音一个角色并保存。
3. 选择未静音角色发送消息，确认气泡上显示角色名。
4. 选择静音角色，先确认普通发送被拒绝，再勾选强制发言验证成功。
5. 切换到「按列表轮换」，连续发送两条消息，确认角色按顺序变化。
6. 刷新页面，确认成员顺序、静音状态、群聊策略和消息身份保持。
7. 模拟上游失败，确认消息可重试且不会增加重复用户消息。

截图脚本：

```bash
python scripts/screenshot.py
```
